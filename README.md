# Unity WebGL Launcher

**Один билд. Одно окно. Windows и macOS.**

Простое Windows-приложение для запуска локальных Unity WebGL-билдов в браузере компьютера или на телефоне в той же Wi-Fi-сети. Не нужно устанавливать Python, настраивать сервер или вводить команды. Для macOS доступны отдельные сборки Apple Silicon (arm64) и Intel (x64).

[Скачать готовое приложение](https://github.com/CodeWizaard/Unity-WebGL-Launcher-Windows-macOS/releases/latest) · [Сборки и проверки](https://github.com/CodeWizaard/Unity-WebGL-Launcher-Windows-macOS/actions)

## Как пользоваться

1. Скачайте ZIP под свою систему из Releases и распакуйте его.
2. Запустите `Unity WebGL Launcher.exe`.
3. Выберите `index.html` или папку WebGL-билда, содержащую `index.html`.
4. Выберите **Только этот компьютер** или **Телефон по Wi-Fi**, нажмите **Запустить**.
5. Браузер компьютера откроется автоматически. Для телефона скопируйте показанный адрес и откройте его на телефоне.

Кнопка **Остановить** и закрытие окна останавливают сервер. Свободный порт выбирается автоматически.

В режиме **Телефон по Wi-Fi** в списке может быть две ссылки или больше, если у компьютера несколько IP-адресов, например от Wi-Fi, Ethernet или VPN. Все ссылки ведут к одному билду. Если первая ссылка не открывается на телефоне, выберите другую. QR-код и кнопка **Копировать** используют выбранную ссылку. Кнопка **Открыть в браузере** открывает билд на самом компьютере по адресу `127.0.0.1`.

Приложение доступно для Windows x64 и macOS (Apple Silicon / Intel). Сборка не подписана сертификатом разработчика, поэтому система может потребовать дополнительное подтверждение открытия. Не отключайте защиту системы; при необходимости используйте запуск из исходников.

### Предупреждение «Система Windows защитила ваш компьютер»

SmartScreen учитывает цифровую подпись и репутацию скачанного приложения. Этот выпуск пока не имеет доверенной подписи издателя. Иконка, сведения о версии, ZIP-архив или собственный самоподписанный сертификат не устраняют предупреждение.

Для прямого распространения EXE разработчику нужна доверенная подпись кода с отметкой времени. Даже OV/EV-сертификат не гарантирует немедленного исчезновения предупреждения: новому приложению может понадобиться репутация. Альтернатива — публикация MSIX через Microsoft Store, где подписью распространяемого пакета занимается Microsoft. В текущем репозитории Store-пакет и сертификат не настроены.

См. [SmartScreen для разработчиков](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation) и [варианты цифровой подписи](https://learn.microsoft.com/windows/apps/package-and-deploy/code-signing-options).

## Что поддерживается

- Обычные файлы, Gzip (`.gz`), Brotli (`.br`) и Unity Decompression Fallback (`.unityweb`).
- Правильные MIME-типы, в том числе `application/wasm`, и `Content-Encoding` для сжатых файлов.
- Заголовки COOP/COEP для изоляции страницы, отключённое кэширование при локальной разработке.
- Имена папок и файлов с пробелами и кириллицей.
- Только чтение файлов, запрет обхода папки, скрытых путей, символических ссылок и просмотра каталогов.
- Никаких аккаунтов, телеметрии, рекламы и внешних сервисов.

## Телефон по Wi-Fi: ограничения HTTP

Компьютер и телефон должны быть в одной локальной сети. Гостевая сеть, изоляция устройств на роутере, VPN или брандмауэр могут блокировать подключение. Если Windows спрашивает о сетевом доступе, разрешайте его только для доверенной частной сети.

Это HTTP-сервер для предпросмотра, без HTTPS и авторизации. В режиме Wi-Fi все обычные файлы выбранной папки доступны другим устройствам сети до остановки сервера. Выбирайте отдельную папку билда; не папку Unity-проекта или личных документов. Не открывайте порт в интернет.

| Возможность | Этот компьютер (`127.0.0.1`) | Телефон (`http://IP`) |
| --- | --- | --- |
| Несжатый билд / Gzip | Поддерживается | Поддерживается браузером |
| Brotli без fallback | Зависит от браузера; предпочтителен HTTPS | Обычно требует HTTPS; используйте Gzip или fallback |
| Decompression Fallback | Поддерживается Unity loader | Поддерживается Unity loader |
| Потоки / SharedArrayBuffer | Возможны при поддержке браузера и корректном билде | Нужен HTTPS; одних COOP/COEP недостаточно |
| API, требующие secure context | Loopback считается доверенным контекстом | Нужен HTTPS |

Для первой проверки на телефоне рекомендуются **Gzip** или включённый **Decompression Fallback**, без многопоточности. Для Addressables, загружаемых по HTTP, проверьте настройку Unity **Allow downloads over HTTP**. Производительность, доступная память и поддержка WebGL зависят от устройства и версии Unity. Лаунчер не меняет и не пересобирает билд.

Внешние ресурсы могут блокироваться COEP, если их сервер не присылает необходимые CORS/CORP-заголовки.

Документация: [Unity — развёртывание Web-билда](https://docs.unity.com/en-us/engine/6000.5/manual/platform-specific/webgl/building-distribution/deploying), [MDN — secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts).

## Запуск из исходников

Нужен Python 3.10+ с Tk (обычная установка с python.org; для сборок CI используется 3.12). Для QR-кодов установите зависимости: `python -m pip install -r requirements.txt`.

```sh
python -m unity_webgl_launcher
```

На macOS команда обычно называется `python3`.

## Разработка и сборка

```sh
python -m unittest discover -s tests -v
python -m pip install -r requirements-build.txt
python scripts/build.py
python scripts/check_bundle.py
python scripts/package.py
```

Собирать нужно на целевой ОС: Windows создаёт переносимый `.exe`, macOS — `.app`. ZIP с лицензией и SHA-256 появляется в `release/`. PyInstaller упаковывает Python и Tk вместе с приложением.

Иконки включены в исходники в `unity_webgl_launcher/assets/`: редактируемый SVG, PNG и ICO с несколькими размерами. Для воспроизведения рисунка используйте `python scripts/create_icon.py` (требуется Pillow; для обычной сборки он не нужен). Сведения Windows о версии находятся в `scripts/windows-version.txt`.

GitHub Actions выполняет тесты сервера, сборку и проверку готового приложения на Windows x64 и macOS 15 (arm64 и x64). Тег `v*` публикует архивы в GitHub Releases после успешных проверок. Автоматическая проверка не заменяет ручной запуск настоящего Unity-билда на конкретном устройстве.

Проект вырос из локальных PowerShell/BAT и Python/shell-скриптов. Оригинальные папки, дубликаты и архивы остаются локально и не включаются в репозиторий.

## macOS

Скачайте `macos-arm64` для Apple Silicon или `macos-x64` для Intel. Распакуйте ZIP и откройте Unity WebGL Launcher.app. Python устанавливать не нужно. Первый выпуск проверяется автоматически на macOS 15; более старые версии macOS не проверены.

Приложение не подписано сертификатом Developer ID и не нотарифицировано Apple. Gatekeeper может заблокировать запуск; для доверенной загрузки используйте штатное разрешение в «Системные настройки → Конфиденциальность и безопасность». Не отключайте защиту целиком.
